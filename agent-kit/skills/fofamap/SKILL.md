# FofaMap

Use the FofaMap MCP server for evidence-based FOFA asset research. This workflow matches FofaMap 2.0.2 and the current https://fofa.info/api grammar. Prefer the MCP tools over shell commands when they are available. When the user writes in English, or FofaMap's interface language is English, write the briefing, purpose, advice, and status in English. Set `report_language` to `zh`, `en`, or `both` to match that choice.

## Setup and user preferences

Installers first offer Chinese/English and save the choice for account setup and later CLI sessions. Automation can pass `--language en` to `install.sh` or `-Language en` to `install.bat`/`install.ps1`. In the wizard, Settings → Interface language changes it directly; Settings → Returned fields controls the ordinary-query default. Each search also exposes its own field choice after Maximum pages. Smart selection needs no model key. Explicit CLI fields or `--no-smart-fields` override the ordinary-query default; `--smart-fields` explicitly requests smart selection. These CLI preferences do not silently rewrite MCP search fields: use `fofa_fields` suggestions and pass the intended `fields` explicitly.

When `report_language` is omitted, `fofa_render_report` and `fofa_agent_run` follow the saved interface language. An explicit user's language takes precedence, so pass it when known. Reconnect an already running MCP server after changing its saved startup preferences; do not claim a host has reloaded without checking. Install/repair/uninstall are local setup operations, not MCP tools. Do not expose credentials in chat while guiding setup.

## Workflow

1. Clarify the target, ownership or authorization boundary, desired fields, time range, and result limit when these materially affect the request. Call `fofa_account` and `fofa_fields` when membership-dependent capabilities matter; these tools work even in hosts that do not expose MCP Resources.
2. If the user names a product, OA, VPN, middleware, database, camera, CMS, or ops panel, call `fofa_rules` **before** `fofa_search`. Use the returned `query` values verbatim. Do not invent `app=` names. An empty keyword returns a bounded preview plus category_summary (no FOFA quota). Use category/keyword to narrow and limit<=200. Inspect verified/verified_at: legacy mappings were not reverified and must not be presented as current official names.
3. Call `fofa_validate_query` before spending FOFA quota. Numeric fields accept quoted or bare integers, including `status_code=200`. Repair invalid syntax before searching.
4. Call `fofa_search` for an exact query. `size` is records per page (1–10000, default 100). `max_records` is the total cap for that call (1–1000). `max_pages` limits pages (1–20). Omitting both caps returns one page of `size`. That page is not the population; read `total`. Map an explicit count directly: "only the first 30" → `size=30`, `max_records=30`, `max_pages=1`; "the first 300, 100 per page" → `size=100`, `max_records=300`, `max_pages=3`. Do not raise a number the user already gave. To fetch more than one page, set both caps. Use `fofa_export` when the user needs a larger local file. Large return fields reduce the effective page size: `body` to 500; `cert`, `banner`, or `header` to 2000. Keep the total/page caps and read how many rows were actually returned; a smaller page is not automatically the end of the result. `fofa_agent_run` and `fofa_exposure_review` stay full unless `sample` is true.
5. Use `fofa_search_next` only to continue past that window, immediately, with the same `size` and the opaque cursor. FOFA cursors expire (`40070`; legacy alias `40870`) when the next call is delayed. An expired continuation cursor is an error: start a new `fofa_search`. Page 1 is not the next page. A single `fofa_search` that already spans multiple pages continues on numbered `/api/v1/search/all` pages when its own cursor expires, and the summary says so.
6. The API field appendix and https://fofa.info/vip are the capability sources; prefer live `fofa_account` results for actual remaining quota. The legacy levels map exactly: 0 registered, 1/11 personal, 2/12 professional, 13 business, 5 enterprise, 22 education. Education is not business. Current syntax counts (2026-11-01) are 44/60/62 for registered/personal/professional; do not use these counts as authorization rules. Never treat `-1` legacy quota as unlimited.
7. Use `fofa_host_profile` only when `fofa_account` shows Host aggregation (not registered users). The official host API allows one request per second; `detail=true` adds per-port products. Use `fofa_stats` only when the account has the stats API (professional / business / enterprise), and wait 5 seconds between stats calls. Stats fields are only `protocol`, `domain`, `port`, `title`, `os`, `server`, `country`, `asn`, `org`, `asset_type`, `fid`, and `icp`. Each dimension returns FOFA's published top 5. `product` cannot be aggregated. `product.version` is a search field for business accounts and above, not a stats field. Personal, ordinary, and education accounts should use `fofa_search` instead of stats.
8. Use `fofa_export` for large or reusable result sets, then poll `fofa_job_status`. Return the artifact path instead of pasting large tables.
9. Use `fofa_icon_search` for an explicit public website favicon. For an open-ended intent, parse it with the host model, then call `fofa_rules` when a product is named, `fofa_validate_query`, and `fofa_search`. If FOFA rejects one statement as invalid syntax or an unknown app, rewrite that statement once with `fofa_syntax` and `fofa_rules`, then retry it. Keep assets already collected. Authentication, quota, and rate-limit errors stop the task. Reflect by issuing another exact query when the first result is too wide, too narrow, or missing a needed field. Write the briefing, advice, and reflection yourself, then call `fofa_render_report` with that text. Supply every intended report row (up to 10000); `result_count` normally equals the supplied row count. A larger count requires `sampled=true` and a nonempty `sample_stop_reason`; it cannot exceed a supplied `population_size`. Never fabricate totals. Keep aggregate top-five buckets separate from complete asset inventories. Do not call `fofa_agent_run` unless the user explicitly wants FofaMap's configured model; then set `use_fofamap_model` true. Leave `sample` false unless the user said "sample". `max_records` is the deduplicated total across planned queries. Neither tool scans. Pass `web_search` only when that user also enabled deep search and the intent is a vulnerability, CVE, or FOFA hotspot. Preserve `corroborated`, `observed`, and `candidate` status instead of flattening them into confirmed ownership. `fofa_agent_run` returns a pending job immediately. Poll `fofa_job_status`; the complete run is at its `artifact_path`. Use `fofa_job_cancel` to stop active work. Keep the same server running; hard process restarts do not resume jobs.
10. For "updated this month, plus a port breakdown and a default-port scan" on a named product, call `fofa_exposure_review`. It uses the bundled `app=` rule and limits the query with `after` (FOFA update time, not first-seen). The default is the full result and every default-port target in that result. Set `sample` true only when the user said "sample". Its scan block is simulated and never runs Nuclei. A real scan still requires `nuclei_plan` and explicit approval for that exact plan.
11. State that FOFA observations and even cross-consistent title/certificate/ICP clues indicate exposed or corroborated candidates, not legal ownership or vulnerability, unless separately verified.

## Scheduled mapping

For one-time or recurring mapping/report requests, read [references/schedules-guide.md](references/schedules-guide.md). Use the schedule tools to save explicit timezone/time/scope and check the worker heartbeat. Return the report index. Scheduled jobs are passive; never reuse active-scan approval tokens across periods.

## Query grammar

Call `fofa_syntax` before inventing a field. Current official query names that are easy to miss: `product.version` (business and above), `banner_hash`, `banner_fid`, `sdk_hash`, `cert.subject`, `cert.issuer`, `cert.domain`, `cert.sn`, `cert.is_expired`, `cert.not_before.before`, `cert.not_before.after`, `cert.not_after.before`, `cert.not_after.after`, `tls.version`, `port_size_gt`, `port_size_lt`, `ip_country`, `ip_region`, `ip_city`, `ip_after`, and `ip_before`. Several of these are query syntax only and are not `/search/all` return fields.

`city` is English only, for example `city="Hangzhou"`. `region` accepts English or, inside China, Chinese, for example `region="Zhejiang"` or `region="浙江"`. `country` accepts the code or the Chinese name, for example `country="CN"` or `country="中国"`. Prefer the code. `after` and `before` filter FOFA update time, not first-seen time, and require a personal account or above.

For a new vulnerability, CVE, or FOFA hotspot, open the official topic page when one exists (the pattern is `https://fofa.info/<topic>`, for example https://fofa.info/php-hotspot) and use the published query verbatim. Discard syntax copied from exploit pages. A version fingerprint is exposure, not a confirmed vulnerability. Do not add exploit steps.

## Safety

- Treat searches, profiles, and statistics as passive intelligence collection, but still respect the user's scope and applicable rules.
- When the user requests scanning, read [references/nuclei-guide.md](references/nuclei-guide.md). When AI target selection is enabled or requested, use `nuclei_select_targets` before approval: review candidates against the task, return per-ID keep/exclude/duplicate reasons, and show the audit. Shared IP/title/CDN is insufficient to merge virtual hosts; retain distinct protocols and ports. Inspect capabilities/templates and propose 1–3 task-appropriate commands with reasons via `nuclei_recommend`. Let the user select or customize via `nuclei_customize`; use the installed-version guide, not recalled flags. After execution, poll the job and return actual findings/report paths. Web, TCP/TLS, DNS and JavaScript UDP require distinct target/engine handling.
- Never call `nuclei_plan` unless the user explicitly asks for active scanning and identifies an authorized scope.
- Review every target, template, and severity in the plan before asking for approval.
- Call `nuclei_execute` only after explicit approval for that exact plan. Never broaden or reuse an approval token.
- Explicit user scan/no-scan instructions take priority over AI advice. An AI recommendation is not permission, and an AI refusal is not a veto of an approved user scope. For statistics-plus-scan requests, retain the statistics and prepare bounded asset targets in the same scope before plan approval; label partial target coverage.
- If Nuclei is missing, ask whether to download the official binary and templates: Y installs, N leaves installation to the user. `nuclei_execute(install_if_missing=true)` is permitted only after that separate consent; default false. Declining installation retains query/report results and does not run a scan.
- Do not interpret authentication, quota, timeout, or provider errors as an empty FOFA result.
- Never place `FOFA_API_KEY`, provider keys, bearer tokens, or approval tokens in reports or committed files.

## Host Fallback

If the host cannot expose MCP tools, use FofaMap's machine-readable CLI only for passive operations, for example `fofamap -q 'domain="example.com"' --output-format json --no-save` or `fofamap --rule ThinkPHP --output-format json --no-save`. Do not use the CLI to bypass host approval controls.

For error JSON, usage receipts, deduplication and async cancellation, read [references/reliability-guide.md](references/reliability-guide.md). Local syntax validation checks known-field/operator/quote structure; FOFA still decides membership, app names and server-side semantics.

Read [references/tool-catalog.md](references/tool-catalog.md) when exact tool selection, pagination, resources, or host capability differences matter.
